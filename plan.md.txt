# Проект: автоматизированный пайплайн трукрайм-контента для TikTok (оригинальный контент)

## Контекст

Цель — построить мультиагентную систему, которая производит трукрайм-видео для TikTok с нуля (не перезаливая чужие видео), чтобы не нарушать авторские права и не попадать под копирайт-страйки/бан аккаунта. Вместо нарезки чужих YouTube-видео система:
1. сама исследует и пишет сценарий по реальному делу (факты не защищены копирайтом — защищено только конкретное произведение),
2. подбирает архивные фото/видео из юридически чистых источников,
3. монтирует финальное видео с собственной озвучкой.

Проект стартует с нуля (пустая директория, не git-репозиторий) — это greenfield-разработка, а не изменение существующей кодовой базы.

Решения, принятые пользователем:
- **Поиск историй**: LLM ищет по открытым источникам (веб-поиск) и пишет структурированный бриф со ссылками на источники.
- **Источники медиа**: приоритет — точно безопасные public domain (Wikimedia Commons, NARA, Library of Congress, Internet Archive); AI-генерация изображений как fallback; мугшоты/полицейские фото — с обязательной пометкой "требует проверки юрисдикции" (это единственный источник с реальным юридическим риском, поэтому он не должен использоваться полностью автоматически).
- **TTS**: Piper (open-source, локально, бесплатно).
- **Стек/среда**: Python, запуск локально на машине пользователя.

## Архитектура пайплайна (8 агентов)

```
1. Story Research  →  2. Script Writer  →  3. Archive Finder  →  4. Voiceover
                                                                       │
8. Analytics  ←  7. Publisher  ←  6. Metadata  ←  5. Video Assembly ◄─┘
        │
        └── фидбэк → Story Research / Script Writer (какие темы/хуки заходят)
```

### 1. Story Research Agent
- Вход: тема/ниша (опционально) или "найди новое дело".
- Веб-поиск (через LLM с web-поиском) по хорошо задокументированным делам (Wikipedia, судебные архивы, новостные статьи).
- Выход: `brief.json` — факты, таймлайн событий, действующие лица, ссылки на источники, флаг чувствительности (текущее расследование / несовершеннолетние жертвы / живые подозреваемые без приговора → откладывать в ручной review).

### 2. Script Writer Agent
- Вход: `brief.json`.
- LLM превращает факты в серию сценариев "Part 1, 2, 3…" (~150-170 слов на часть ≈ 60-70 сек озвучки — с учётом, что TikTok Creator Rewards Program требует минимум 1 минуту для монетизации).
- Каждая часть заканчивается клиффхэнгером. Внутри сценария — раскадровка: список "сцен" с ключевыми словами для подбора визуала (например: `{"text": "...", "visual_query": "1970s police station exterior"}`).
- Выход: `script.json`.

### 3. Archive Finder Agent
- Вход: `script.json` (список visual_query по сценам).
- Поиск по API: Wikimedia Commons API, NARA Catalog API, Library of Congress API, Internet Archive API — только ассеты с явной public domain/CC0 лицензией, сохраняем лицензионные метаданные в манифест.
- Если ничего не найдено — fallback на AI-генерацию изображения (по описанию сцены) через image-gen API.
- Мугшоты/полицейские фото — отдельная ветка: агент помечает кандидата, но **не** использует автоматически; кладёт в `review_queue.json` для ручного подтверждения (юрисдикция дела определяет легальность коммерческого использования).
- Выход: `media_manifest.json` (путь к файлу, источник, лицензия, сцена).

### 4. Voiceover Agent
- Вход: `script.json`.
- Piper TTS генерирует аудио на каждую часть + word/sentence-level таймкоды (для синхронизации субтитров и Ken Burns эффекта).
- Выход: `audio/part_N.wav` + `audio/part_N_timestamps.json`.

### 5. Video Assembly Agent
- Вход: `media_manifest.json` + аудио + таймкоды.
- ffmpeg/moviepy: Ken Burns pan/zoom на фото, обрезка видео-клипов под сцены, синхронизация с озвучкой, burn-in субтитры (по таймкодам), бампер "Part N", 9:16 crop, брендинг/watermark.
- Выход: `video/part_N.mp4`.

### 6. Metadata Agent
- LLM генерирует заголовок, описание, хэштеги для каждой части (с учётом "part N of M", cliffhanger-teaser).

### 7. Publisher Agent
- Публикация через официальный **TikTok Content Posting API** (требует регистрации приложения и апрува — это отдельный шаг с ожиданием, не мгновенный).
- **Рекомендация: ручной approval-гейт перед первым автопостом**, пока не наработана уверенность в качестве контента и юридической чистоте медиа (особенно пока используются мугшоты/архивные фото по чувствительным делам).
- Планировщик публикаций (расписание частей сериала).

### 8. Analytics Agent
- Забирает метрики через TikTok API (просмотры, retention, completion rate).
- Пишет отчёт, обновляет "что работает" для Story Research (темы) и Script Writer (стиль хуков).

## Оркестрация и структура проекта

Локальный Python-проект, SQLite для состояния пайплайна (простая очередь через таблицу статусов, без Celery/Redis на старте — избыточно для локального запуска).

```
tiktok-crime-project/
  agents/
    story_research.py
    script_writer.py
    archive_finder.py
    voiceover.py
    video_assembly.py
    metadata.py
    publisher.py
    analytics.py
  orchestrator/
    db.py            # SQLite: cases, parts, media_assets, publish_log, metrics
    pipeline.py       # запускает стадии по порядку для case_id, хранит статус/ошибки
  data/
    cases/<case_id>/
      brief.json
      script.json
      media_manifest.json
      review_queue.json
      audio/
      video/
  config.py           # ключи API из .env
  requirements.txt
  run_pipeline.py      # CLI: python run_pipeline.py --case-id X [--stage story|script|archive|voice|assemble|metadata|publish|all]
```

Ключевые библиотеки: `anthropic` (LLM-агенты + web search), `piper-tts`, `ffmpeg-python`/`moviepy`, `requests` (Wikimedia/NARA/LoC/Internet Archive API), `python-dotenv`, `sqlite3` (stdlib).

## Порядок реализации

1. **Каркас**: `orchestrator/db.py` (схема SQLite) + `run_pipeline.py` (CLI-раннер, читает/пишет статус по стадиям).
2. **Story Research Agent** — первым, т.к. без брифа ничего не работает. Проверить на 1-2 реальных делах вручную, оценить качество фактов и ссылок.
3. **Script Writer Agent** — на основе готового брифа сгенерировать серию сценариев, проверить длину/клиффхэнгеры.
4. **Archive Finder Agent** — интеграция с Wikimedia/NARA/LoC/Internet Archive API, затем AI-генерация как fallback, затем review_queue для мугшотов.
5. **Voiceover Agent** — Piper, проверить качество голоса и таймкоды.
6. **Video Assembly Agent** — самая трудоёмкая часть (ffmpeg Ken Burns + субтитры + синхронизация); тестировать на одном part сначала.
7. **Metadata Agent** — простой, в конце.
8. **Publisher + Analytics** — после регистрации приложения в TikTok Content Posting API (эту заявку стоит подать заранее, т.к. апрув может занять время); Publisher сначала работает в режиме "dry-run" (сохраняет файл + метаданные, без реальной публикации) до ручного одобрения.

## Верификация

- Каждая стадия тестируется отдельно на одном тестовом деле (`--case-id test1 --stage story`, затем `--stage script` и т.д.), с ручной проверкой промежуточного JSON/файлов перед переходом к следующей стадии.
- End-to-end: прогнать полный пайплайн на одном деле от Story Research до готового `video/part_1.mp4`, посмотреть видео глазами (проверить синхронизацию звука/субтитров/визуала, отсутствие мугшотов без ручного review).
- Publisher тестируется в dry-run режиме, реальная публикация — только после ручного подтверждения первых 2-3 видео.
