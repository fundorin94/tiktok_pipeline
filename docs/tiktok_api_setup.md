# Как получить доступ к TikTok Content Posting API

Это нужно для Publisher Agent, чтобы когда-нибудь переключить `PUBLISH_DRY_RUN=false`
и публиковать реально. Процесс состоит из нескольких шагов с ожиданием апрува —
имеет смысл начать заранее, параллельно с доработкой остального пайплайна.

## 1. Создать аккаунт разработчика

Идите на https://developers.tiktok.com → зарегистрируйтесь (можно через обычный
TikTok-аккаунт). Это бесплатно.

## 2. Зарегистрировать приложение (App)

В консоли разработчика создайте новое приложение — укажите название, категорию,
описание того, что оно делает (честно: "automated content pipeline for a
true-crime video series" — не пытайтесь замаскировать назначение, это скорее
навредит на этапе аудита).

## 3. Добавить продукт Content Posting API

В настройках приложения добавьте продукт **Content Posting API** и включите
**Direct Post** конфигурацию — это разрешает публикацию сразу в профиль
пользователя (а не только черновиком).

## 4. Настроить Login Kit (OAuth)

Content Posting API работает от имени конкретного TikTok-аккаунта — вашего
собственного канала. Для этого нужен **Login Kit**:
- Настроить redirect URI (даже для локального скрипта — можно `http://localhost:PORT/callback`)
- Реализовать OAuth-флоу: пользователь (вы) авторизует приложение → приложение
  получает `access_token` + `open_id` для вашего аккаунта
- Токен даёт доступ к скоупу `video.publish`

## 5. Запросить скоуп `video.publish`

Это отдельное разрешение, которое нужно **запросить и получить одобрение** в
консоли разработчика — не выдаётся автоматически при создании приложения.

## 6. Важный нюанс: неаудированные приложения = только приватный постинг

**Пока ваше приложение не прошло аудит на соответствие TikTok Terms of Service,
весь контент, опубликованный через API, будет виден только вам (private mode)**,
не публично. Это по сути "песочница" для тестирования публикации технически,
без реального выхода на аудиторию.

Чтобы контент стал публичным — нужно отдельно подать заявку на **аудит**
клиента API. Это может занять время (у TikTok нет фиксированного SLA,
закладывайте от нескольких дней до нескольких недель).

## 7. Технические требования к видео

- Формат: **MP4, кодек H.264** — у нас уже так (`agents/video_assembly.py`
  выдаёт ровно это: `-c:v libx264 -pix_fmt yuv420p`)
- Публикация либо загрузкой файла напрямую, либо по проверенному URL
  (если используете URL-загрузку — потребуется верификация домена/сайта)

## Практический план

1. Пройти шаги 1-4 уже сейчас — это не требует одобрения, можно сделать за
   один вечер.
2. Протестировать публикацию в приватном режиме (неаудированный клиент) —
   это уже позволит переключить `PUBLISH_DRY_RUN=false` и проверить, что
   Publisher Agent реально достучится до API технически, без риска публичной
   публикации сырого контента.
3. Параллельно — вручную закрыть `review_queue.json` / `manual_sourcing_queue.json`
   по тестовым кейсам и накопить несколько готовых, проверенных видео.
4. Только когда контент и процесс обкатаны на приватном режиме — подавать
   на аудит для публичной публикации.
